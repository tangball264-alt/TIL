# 참조 타입

## java의 타입

1. 기본형 타입
- 논리형
- 문자형
- 정수형
- 실수형

2. 참조형 타입
- 기본 자료형 타입 8가지를 제외한 나머지 전부
- 실제 값이 아닌 객체의 주소 값(메모리 주소) 저장
- 클래스, 인터페이스, 배열, 열거형(Enum) 등
- 클래스 타입에는 String과 사용자 정의 클래스, 래퍼 클래스 등이 속함
- 인터페이스 타입에는 리스트, Runnable 등이 속함.
- 열거 타입(Enum)에는 Day, Role 등이 속함.

예를 들어서 배열(int[]), String, Integer 등.

### 배열
```java
int[] a = {1, 2, 3};
System.out.println(a);
```
따라서 이렇게 하면 1, 2, 3이 아니라 위 배열의 주소값이 나온다.

```java
System.out.println(Arrays.toString(a));
```
와 같은 방식으로 [1, 2, 3] 형태의 값을 출력 가능.


## 원시 타입(Primitive Type)과 참조 타입의 차이

|항목|원시 타입 (Primitive Type)|참조 타입 (Reference Type)|
|---|------------------------|-----------------------|
|저장 위치|스택 메모리|힙 메모리에 객체가 저장되고, 참조는 스택에 저장됨|
|데이터 크기|고정 크기 (예: int는 4바이트)|객체마다 다름 (객체의 필드에 따라 달라짐)|
|Null 허용 여부|Null 값을 가질 수 없음|Null 값을 가질 수 있음|
|기본 값|타입에 따른 기본 값 (예: int는 0)|Null|
|값 비교 방식|값 자체를 비교|참조(메모리 주소)를 비교|
|메모리 효율성|메모리 사용량이 적음|상대적으로 메모리 사용량이 큼|
|성능|고속 (직접 값 처리)|느림 (객체 참조 처리)|
|오토박싱/언박싱|적용되지 않음|원시 타입과 상호작용 시 오토박싱/언박싱 필요|
|사용 용도|간단한 값 저장 (숫자, 논리값 등)|복잡한 데이터 구조나 객체 저장|

## 래퍼 클래스

기본 자료형(Primitive Type)을 객체(Object) 형태로 감싸서 다룰 수 있도록 만든 참조 자료형

| 분류 | 기본 타입 (Primitive Type) | 박싱된 타입 (Boxed Type / Wrapper Class) |
| 정수 | byte, short, int, long | Byte, Short, Integer, Long |
| 실수 | float, double | Float, Double |
| 문자 | char | Character |
| 논리 | boolean | Boolean |


### 박싱과 언박싱

박싱 : 기본 타입의 값을 박싱된 래퍼 타입 객체로 만드는 과정

int -> Integer

언박싱 : 박싱된 래퍼 타입 객체에서 기본 타입의 값을 꺼내는 과정.

Integer -> int


#### 오토 박싱과 언박싱

자바 5부터 컴파일러가 자동으로 박싱과 언박싱 수행.

Auto-boxing

```java
int num = 10;
Integer boxedNum = num; //오토박싱 발생
```

Unboxing

```java
Integer boxedNum = 10;
int num = boxedNum; //언박싱 발생
```


주의 : 성능에 영향을 줄 수 있음


### 사용 이유

**왜 Boxed Type을 쓰는가**

1. 컬렉션 프레임워크 사용 : ArrayList, HashMap 등의 자바 컬렉션은 기본 타입을 넣을 수 없음.
2. null값 허용 : 기본 타입은 타입별 기본값을 넣지 null값을 넣을 수 없음.
3. 제네릭 활용 : 제네릭 타입 파라미터에는 참조 타입만 사용 가능.

*제네릭 타입* : 클래스나 메서드에서 사용할 데이터 타입을 미리 정하지 않고, 나중에 객체를 생성할 때 외부에서 지정하도록 만드는 기능

```java
List<String> list = new ArrayList<>(); // String 타입을 파라미터로 전달
```


### 주의 사항

1. 성능 및 메모리 오버헤드가 발생.
2. == 연산자로 값 비교 불가. .equals()사용해야 함.
3. NullPointerException위험. 값 null일때 언박싱되면 오류남.
