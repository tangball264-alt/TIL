# docker

## 개요

**Docker**는 애플리케이션을 구축, 배포, 실행, 업데이트 및 관리할 수 있는 오픈 소스 플랫폼이다.

> 출처 : https://kr.linkedin.com/pulse/beginners-guide-docker-treinetic-hvkdc?tl=ko

## 특징

도커는 **컨테이너(Container)**라고 부르는 느슨하게 격리된 환경에서 애플리케이션을 패키징하고 실행할 수 있는 기능을 제공함.

격리성과 보안성 덕분에 호스트가 여러 컨테이너를 동시 실행할 수 있음.

컨테이너 특성상 경량이며, 애플리케이션 실행에 필요한 모든 것을 포함하기에 호스트에 설치된 것에 의존할 필요가 없다.

작업하는 동안 컨테이너를 공유하고, 공유받은 이들이 동일한 방식으로 작동하는 컨테이너를 얻을 수 있다.

컨테이너 : 애플리케이션과 이를 실행하기 위해 필요한 모든 파일을 하나로 묶어, 어떤 환경에서도 동일하게 작동하도록 격리된 실행 환경을 제공하는 기술
- 독립된 격리 환경과 높은 이식성
- 동시에 VM과 달리 호스트 OS의 커널을 공유하기에 경량성을 띈다.

## 장점

1. 애플리케이션의 신속하고 일관된 인도
개발자가 로컬 컨테이너를 통해 표준화된 환경에서 작업할 수 있게 하여 개발 라이프사이클을 효율화.

컨테이너는 지속적 통합 및 지속적 제공(CI/CD) 워크플로우에 적합

2. 신속한 배포와 확장
도커의 컨테이너 기반 플랫폼은 높은 이식성을 제공.
도커의 이식성과 경량성 특성으로 비즈니스 요구에 따른 실시간 확장과 축소가 가능하여 워크로드의 동적 관리가 쉽다.

3. 동일 하드웨어에서 더 많은 워크로드 실행
도커는 하이퍼바이저 가상머신에 비해 경량이며 빠르기 때문에 서버 용량을 더 많이 활용할 수 있다.


## 다른 비슷한 것.

1. 포드만
- 도커와 호환되는 cli명령어를 제공하는 컨테이너 엔진.
- daemonless, rootless 기능을 제공하는 것이 특징.

2. 컨테이너디
- 도커 내부에서도 사용되는 오픈소스 로우 레벨 컨테이너 런타임.
- 기능은 적지만 가볍고 빠르다.
- 쿠버네티스 환경에서 도커의 부가기능을 배제하고 직접 컨테이너를 구동하고 관리할 때 표준적으로 사용됨.

3. LXD/LXC
- 통칭 리눅스 컨테이너.
- 단일 애플리케이션을 패키징하는 도커와 달리, 리눅스 OS 시스템 자체를 컨테이너화해 하나의 독립된 가상머신처럼 환경을 구축, 격리하는 기술.

## 도커 이미지

**이미지** : 도커 컨테이너를 생성하기 위한 지침이 담긴 읽기 전용(read-only) 템플릿. 

기본적으로 제공되는 이미지를 사용하거나, 그렇게 제공되는 이미지를 기반으로 추가적인 사용자 정의를 한 새로운 이미지를 사용하거나.

이미지 생성과 실행을 위해 도커파일(Dockerfile)을 작성해야 한다.

이미지는 레이어 구조로, 도커파일의 각 지시어가 하나의 레이어가 된다.

이후 도커파일을 수정하고 다시 빌드할 때, 수정사항이 있는 레이어만 다시 빌드되기에 도커 이미지는 매우 가볍고, 작고, 빠르다.
