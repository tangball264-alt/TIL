# HTTPS

## 개요

**H**yper**T**ext **T**ransfer **P**rotocol over **S**ecure Socket Layer

일반 [HTTP](https.md#http)에 보안(Secure)이 추가된 형태. 

암호화-복호화를 거쳐 보안성을 높인다.

웹서버 <-> 인터넷 브라우저(클라이언트)간 문자 전송을 위한 **통신규약**으로서, 웹서버와 브라우저 간 암호화 된 연결을 설정하는 표준 보안 기술이다.




## http

HyperText Transfer Protocol

https와 마찬가지의 역할을 갖는 통신 규약

### http 특징

1. 80번 포트 사용
2. 클라이언트가 요청을 보내는 경우에만 서버가 응답하고 연결을 끊는 단방향적 통신
3. 암호화 없이 평문 데이터를 주고받는다.


### HyperText

마우스 클릭만으로 필요한 정보로 직접 이동할 수 있는 방식.
[흔히 말하는 링크](https.md#hypertext)기술. 

이러한 하이퍼텍스트를 교환하기 위한 프로토콜이 http

## SSL

https의 's'가 의미하는 것.

Secure Socket Layer의 약칭.

- '보안 계층' 이라는 하나의 독립적인 프로토콜 계층.

- 이 위에 http프로토콜을 얹어 보안된 http통신을 하는 것이 https

### 특징

**핸드셰이크 후 전송**

>1. 인사하기(Client Hello)
>
>- 브라우저(클라이언트)가 서버에게 보내는 인사.
>
>- 클라이언트의 브라우저가 지원하는 암호화 방식(Cipher Suite)을 제시 
>
>- +랜덤 데이터 생성해 추가 전송
>
>2. 인사하기(Server Hello)
>
>- 서버가 클라이언트(브라우저)에게 보내는 인사
>
>- 제시된 암호화 방식 중 하나를 선정하여 알려줌.
>
>- 추가로 서버 인증서(서버 공개키 포함) 전달. 
>
>- +서버가 생성한 랜덤 데이터도 추가로 전송
>
>3. 비밀 키 만들기(Client key exchange)
>
>- 클라이언트는 인사 단계에서 나온 두 랜덤 데이터를 조합해 이후 사용할 키(대칭키)를 만든다.
>
>- 그리고 그 키를 서버에게 받은 공개키로 암호화하여 서버에 전송한다.
>
>- 서버가 자신의 개인키로 잠금을 풀어 이 대칭키를 꺼낸다.
>
>- 이제 둘은 '오직 둘만 아는' 비밀키를 확보
>
>4. Client, Server Finished
>
>- 이상으로 핸드셰이크 과정이 정상적으로 마무리되었기에 클라이언트와 서버 모두 finished 메시지를 보냄.
>
>5. 이제 **전송**단계. 대칭키로 통신한다.

*보다 정확히는, 여기서 CA(인증서 발급 기관)이라는 제3자가 추가될 수 있다. 인사 단계에서 서버가 제공하는 인증서를 발급해주는 기관임.*

보안성이 높은 비대칭키와 속도가 빠른 대칭키 방식을 혼합하여 이점을 얻는다.



### TLS

Transport Layer Security

1999년 SSL 3.0이 표준화되며 변경된 새 명칭.

그러나 여전히 SSL과 혼용된다.
