# 스왑 파일

## 개요
컴퓨터의 물리적 메모리가 부족할 때 하드디스크나 SSD의 일부 공간을 메모리처럼 활용하는 가상 메모리 공간.

메모리 부족으로 인한 OOM 중단 해결 방안.

## 종류
스왑 공간이라는 대분류 안에 전용 스왑 파티션, 스왑 파일, 둘의 조합 등이 포함된 것.



## 생성 방법

> 충분한 디스크 공간이 있을 때 시도한다.
>
> 또한 이는 리눅스/유닉스 환경에서의 예시로 제공된 명령어이다.
>
> 1. 새 스왑 파일의 크기를 nMB로 결정하고, n*1024를 블록 수로 한다.
>
> - ex) 64MB 스왑 파일의 블록 수는 65536
>
> 2. 빈 파일을 생성한다
>
> ```bash
> dd if=/dev/zero of=/swapfile bs=1024 count=65536
> ```
> - dd명령어 : 파일을 블록 단위로 읽어 지정한 형태로 변환하고 복사. 전체 디스크 백업, iso이미지 생성, 백업 데이터 복원, 지정 크기의 대용량 파일 생성(ex 스왑파일생성) 등에 사용.
>     - 옵션 if(Input File) : 읽어올 원본 파일을 지정. 빈 상태의 스왑 파일을 만들기 위해 무한히 0을 생성하는 가상장치(/dev/zero)를 입력 소스로 지정.
>     - 옵션 of(Output File) : 저장할 대상 파일 지정. 여기서는 새로 만들 스왑 파일의 경로와 이름 작성.(현위치의 swapfile)
>     - 옵션 bs(Block Size) : 한 번에 읽고 쓸 데이터 블록의 크기.
>     - 옵션 count : 복사할 블록의 총 개수. bs만큼을 count번 반복하여 복사한다.
> 3. 명령으로 스왑파일 설정
> ```bash
> mkswap /swapfile
> ```
> 4. 스왑 파일의 보안을 변경해 읽을 수 없게 함.
> ```bash
> chmod 0600 /swapfile
> ```
> - chmod : 디렉토리의 접근권한을 변경. u(파일을 생성한 소유자), g(소유자가 속한 그룹의 인원), o(그외 제3자)에 대해 r(읽기. 4), w(수정, 생성, 삭제. 2), x(프로그램 실행, 디렉토리 진입. 1)의 권한을 결정.
>     - 예시에서는 (0) 6 0 0. 오직 소유자(root)만 읽기+쓰기의 모든 권한을 갖는다. 나머지는 어떤 권한도 없다.(앞의 0은 특수 권한. 0이므로 적용하지 않음.)
> 5. /etc/fstab 파일을 편집해 다음의 항목 추가.
> ```
> /swapfile swap swap defaults 0 0
> ```
> - 대상 파일 경로 지정. 아까 생성한 스왑파일 지정함.
> - 마운트 포인트는 swap. 본래는 경로를 지정하지만, 스왑 파일은 일반 폴더터럼 접근하지 않기에 일반 경로 대신 이렇게 작성.
> - 파일 시스템 타입(대상 파일 포맷 종류)은 스왑 전용 파일 시스템 형태임
> - 마운트 옵션(시스템이 이 공간을 불러올 때 적용할 세부 규칙)은 리눅스의 기본적인 표준 옵션셋(defaults)을 그대로 사용. 실제 내용은 아마 w, r 허용 + **부팅시 자동 로드** 등
> - 백업(dump명령어)가 이것도 백업하는가? -> 아니오(0)
> - 부팅 시 파일 시스템 오류 점검(fsck명령어)을 어느 정도의 우선순위로 받는가? -> 받지 않는다(0)
> 6. 시스템이 5에서 수정한 구성을 등록하도록 다시 마운드 단위 생성
> ```bash
> systemctl daemon-reload
> ```
> 7. 스왑파일 활성화
> ```bash
> swapon /swapfile
> ```
> 8. 다음 명령으로 스왑 파일 공간을 볼 수 있다.
> ```
> cat /proc/swaps
> free -h
> ```
> 출처 : [레드햇 docs 13.5 스왑 파일 만들기](https://docs.redhat.com/ko/documentation/red_hat_enterprise_linux/9/html/managing_storage_devices/creating-a-swap-file_getting-started-with-swap)

## 원리

RAM의 메모리가 가득 차면 OS는 우선순위가 낮은 데이터를 일단 스왑으로 이동시켜 메모리 공간을 확보.

*단, 실제로 꽉 찼을 때 쓰기보다는 스와프니스(swappiness) 값에 따라 물리 메모리의 사용량이 일정 수준 이상이면 스왑을 사용.

## 장점

1. 메모리 부족 해결
2. 시스템 안전성 : RAM 꽉 차서 시스템이 느려지거나 불안정해지는 것을 막는다. 메모리 부족으로 인한 커널 패닉이나 시스템 중단을 예방.
3. 휴면 모드(하버네이션) : 우분투 시스템이 하버네이션 모드로 들어갈 때, 시스템의 현 상태를 디스크의 스왑 공간에 저장. 이후 다시 켤 때 이 내용을 RAM으로 불러오므로 내용이 휘발되지 않음.

## 단점

1. 성능 저하 : 디스크(HDD, SSD)는 필연적으로 물리 메모리보다 느림(특히 HDD). 너무 많은 스왑 사용은 시스템 속도를 저하시킨다.
2. 디스크 사용 횟수 증가 : SSD는 디스크 쓰기 횟수에 따라 수명이 제한된다. 스왑을 너무 자주 쓰면 SSD 수명 저하될수도.
