# 집합 연산자

## 개념

여러 SQL 쿼리결과를 '집합(SET)'으로 간주하고 결과를 결합하는 연산자.
-> 쿼리문 안이 아니라, 두 쿼리문의 사이에 쓴다.

1. 합집합(UNION)
2. 교집합(INTERSECT)
3. 차집합(MINUS/EXCEPT(sql server))

## 합집합

UNION : 합집합. 단, 데이터 정렬 -> 중복 제거 수행
UNION ALL : 합집합 2. 단, 정렬&중복제거 x.

### 예시

**예시 테이블**

[EMPLOYEE_KOREA] 테이블
| EMP_ID | EMP_NAME | DEPT |
|--------|----------|------|
| E001 | 김지훈 | 인사팀 |
| E002 | 이수민 | 개발팀 |
| E003 | 박준형 | 영업팀 |

[EMPLOYEE_USA] 테이블
| EMP_ID | EMP_NAME | DEPT |
|--------|----------|------|
| E005 | 오세훈 | 영업팀 |
| E004 | 정유진 | 마케팅팀 |
| E002 | 이수민 | 개발팀 |

```SQL
SELECT EMP_ID, EMP_NAME
  FROM EMPLOYEE_KOREA

 UNION

SELECT EMP_ID, EMP_NAME
  FROM EMPLOYEE_USA
```

**실행순서**

1. 각 쿼리의 결과 도출 : 

| EMP_ID | EMP_NAME |
|--------|----------|
| E001 | 김지훈 |
| E002 | 이수민 |
| E003 | 박준형 |

| EMP_ID | EMP_NAME |
|--------|----------|
| E005 | 오세훈 |
| E004 | 정유진 |
| E002 | 이수민 |

2. 두 결과 UNION

| EMP_ID | EMP_NAME |
|--------|----------|
| E001 | 김지훈 |
| E002 | 이수민 |
| E003 | 박준형 |
| E005 | 오세훈 |
| E004 | 정유진 |
| E002 | 이수민 |

3. 내부 결합된 데이터를 정렬

| EMP_ID | EMP_NAME |
|--------|----------|
| E001 | 김지훈 |
| E002 | 이수민 |
| E002 | 이수민 |
| E003 | 박준형 |
| E004 | 정유진 |
| E005 | 오세훈 |

4. 중복 데이터 제거

| EMP_ID | EMP_NAME |
|--------|----------|
| E001 | 김지훈 |
| E002 | 이수민 |
| E003 | 박준형 |
| E004 | 정유진 |
| E005 | 오세훈 |


**만약 UNION ALL 이었다면?**

3, 4 단계를 생략.

예상 결과 : 

| EMP_ID | EMP_NAME |
|--------|----------|
| E001 | 김지훈 |
| E002 | 이수민 |
| E003 | 박준형 |
| E005 | 오세훈 |
| E004 | 정유진 |
| E002 | 이수민 |

### 실무 관점

중복 제거 불필요 -> UNION ALL

*정렬과 중복 제거 작업 추가로 인한 성능 부담 최소화*

## 교집합, 차집합

INTERSECT : 교집합. 각 결과의 중복만을 추출.
MINUS(EXCEPT) : 차집합. SQL Server에서는 EXCEPT, 그 외(Oracle등)에서는 MINUS. 합집합에서 교집합을 제외한 형태.


사용 방식은 집합 연산자 공통.

계산 순서도 공통.(각 쿼리 연산 -> 집합 연산 -> 출력)

## 집합 연산자 특징

| 특징 | UNION | UNION ALL | INTERSECT | MINUS(EXCEPT) |
|---|---|---|---|---|
| 정렬 여부 | O | X | O | O |
| 중복 제거 여부 | O | X | O | O |


연산 순서 문제
```sql
query1
UNION
query2
UNION ALL
query3
```
