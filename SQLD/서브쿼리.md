# 서브쿼리(Subquery)

## 개념

한 SQL문에 포함된 다른 SQL문

포함하는 쪽은 Main Query

포함되는 쪽이 Subquery

보다 수준 높은 SQL 조회를 위해 많이 사용된다.

### 특징 및 주의사항

1. 반드시 괄호로 감싸 사용할 것
2. 단일행, 다중행 비교 연산자와 함께 쓸 수 있다.
3. [중첩 서브쿼리] 및 [스칼라 서브쿼리](#스칼라-서브쿼리)에서는 ORDER BY를 사용할 수 없다.
4. [연관 서브쿼리]는 메인->서브 순으로 실행. 비연관 서브쿼리는 서브->메인 순 실행.
5. 서브쿼리는 1:M 관계 테이블을 1쪽 결과 집합으로 만들 수 있다.(조인일 경우 반드시 M쪽으로 결과 집합 생김)

## 분류

1. 스칼라 서브쿼리
- select 문에서 쓰는, 단일행 단일컬럼 출력의 서브쿼리.
2. 인라인 뷰
- form 절 작성되는 멀티행-멀티컬럼으로 반환되는 가상의 테이블.
3. where절 서브쿼리
- 단일행 / 다중행 서브쿼리 (연산자 구분됨)
- 연관 / 비연관 서브쿼리
- 다중 컬럼 서브쿼리
## 스칼라 서브쿼리

Scalar : 단 하나의

**Scalar Subquery** : 결과가 단 하나의 값(1개 컬럼*1개 행)만 나오는 서브쿼리

-> SELECT 문에서 사용

### 예시

[회원] 테이블
| 회원ID | 이름 |
|------|------|
| A0001 | 회원1 |
| A0002 | 회원2 | 
| A0003 | 회원3 |

[회원연락처] 테이블
| 회원ID | 구분코드 | 연락처 |
|------|------|------|
| A0001 | 휴대폰 | 010-111-1111 |
| A0002 | 집전화 | 02-111-1111 |
| A0002 | 집전화 | 02-222-2222 |
| A0004 | 휴대폰 | 010-4444-4444 |

```sql
SELECT A.이름,
      (SELECT B.연락처
         FROM 회원연락처 B
        WHERE A.회원ID = B.회원ID
          AND B.구분코드 = '휴대폰') AS 휴대폰번호
  FROM 회원 A;
```

메인 쿼리의 A.회원ID 별로 1행1열의 값(010-111-1111 or null)이 나온다.

회원 아이디가
1. A0001인 경우
- 회원연락처 B에 A0001과 회원ID가 같으면서 구분코드가 휴대폰인 행이 있는가? -> 있다.
- 해당 행의 연락처 컬럼을 반환한다.
2. A0002인 경우
- 회원연락처 B에 A0001과 회원ID가 같으면서 구분코드가 휴대폰인 행이 있는가? -> 없다.
- null을 반환한다.
3. A0003인 경우
- 2와 동일하다

최종적으로 
[출력]
| 이름 | 휴대폰번호 |
|------|------|
| 회원1 | 010-111-1111 |
| 회원2 | NULL |
| 회원3 | NULL |

### 주의사항
1. 컬럼 수 제한 : 1개 컬럼만 조회할 것
2. 행 수 제한 : 1개 행만 반환될 것
3. 결과 없을 시 : NULL 반환됨
4. ORDER BY 금지 : 스칼라 서브쿼리 안에서는 ORDER BY 사용 불가.

## 인라인 뷰

**인라인 뷰(Inline View)** : FROM절에 서브쿼리를 작성해 그 서브쿼리의 결과를 하나의 테이블처럼 쓰는 것. 
실무에서 많이 사용됨.

### 특징

1. 가상의 테이블 역할 : 여러 행 여러 컬럼 반환 가능
2. 메인 쿼리 컬럼 참조 불가 : 서브쿼리에서 메인 쿼리의 컬럼 참조 불가. *단, Oracle 12c이상에서는 LATERAL 키워드 통해 참조 가능. 시험은 기본적으로 11g 기준 출제.*
3. 독립 실행 가능
4. 별칭 지정 가능 : 인라인 뷰에 별칭을 부여해 메인 쿼리에서 참조.

### 예시

[EMPLOYEE] 테이블
| EMP_ID | EMP_NAME | DEPT | SALARY |
|---|---|---|---|
| E001 | 김지훈 | 인사팀 | 4000 |
| E002 | 이수민 | 개발팀 | 4500 |
| E003 | 박준형 | 인사팀 | 3800 |
| E004 | 정유진 | 개발팀 | 4700 |

```sql
SELECT A.*
  FROM EMPLOYEE A
       , (
          SELECT DEPT, AVG(SALARY) AS AVG_SALARY
            FROM EMPLOYEE
           GROUP BY DEPT
       ) B
 WHERE A.DEPT = B.DEPT
   AND A.SALARY > AVG_SALARY ;
```

**실행 순서와 분석**

1. 인라인 뷰를 먼저 해석해 가상의 테이블 B를 그린다.
| DEPT | AVG_SALARY |
|---|---|---|---|
| 인사팀 | 3900 |
| 개발팀 | 4600 |
- A 테이블과 조인한다. 이 때, WHERE문의 첫 번째 조건에 따라 DEPT값을 기준으로 동등조인한다.
- WHERE 조건에 따라 부서 평균 급여보다 많이 받는 사람만 출력한다.
- SELECT문에 따라 A 테이블의 컬럼 값만을 가져온다.

[결과]
| EMP_ID | EMP_NAME | DEPT | SALARY |
|---|---|---|---|
| E001 | 김지훈 | 인사팀 | 4000 |
| E002 | 이수민 | 개발팀 | 4500 |

## WHERE문 에서 단일행 서브쿼리 사용

**단일 행 서브쿼리** : 실행 결과로 출력되는 *튜플 행이 1개 이하*인 서브쿼리

-> 스칼라 서브쿼리와 달리 반드시 하나의 열(컬럼)을 가질 필요는 없다.

### 예시

[EMPLOYEE] 테이블
| EMP_ID | EMP_NAME | DEPT | SALARY |
|---|---|---|---|
| E001 | 김지훈 | 인사팀 | 4000 |
| E002 | 이수민 | 개발팀 | 4500 |
| E003 | 박준형 | 인사팀 | 3800 |
| E004 | 정유진 | 개발팀 | 4700 |

```sql
SELECT *
  FROM EMPLOYEE
 WHERE SALARY >= (SELECT AVG(SALARY) FROM EMPLOYEE);
```
1. 서브쿼리의 출력결과
| AVG(SALARY) |
|---|
| 4250 |
2. 메인 쿼리
```sql
SELECT *
  FROM EMPLOYEE
 WHERE SALARY >= 4250 ;
```
3. 출력 결과
| EMP_ID | EMP_NAME | DEPT | SALARY |
|---|---|---|---|
| E002 | 이수민 | 개발팀 | 4500 |
| E004 | 정유진 | 개발팀 | 4700 |


**비연관 서브쿼리** : 서브쿼리 -> 메인 쿼리 순으로 실행되는 서브쿼리.

예시의 서브쿼리는 단일행 서브쿼리이면서 비연관 서브쿼리인것.


### 단일행 서브쿼리에 사용될 수 있는 단일행 연산자

**단일행 연산자** : 비교 행의 개수가 1행(또는 NULL)일 때 사용되는 연산자. 2행 이상일 때 사용 시 오류 발생.

대부분 비교 연산자는 단일행 연산자.


```sql
SELECT *
  FROM EMPLOYEE
 WHERE SALARY >= (SELECT AVG(SALARY) FROM EMPLOYEE);
```
이 예시에서 **>=** 등을 말하는 것.

### 예시2

**단일행 서브쿼리 겸 연관 서브커리 케이스 분석**

[EMPLOYEE] 테이블
| EMP_ID | EMP_NAME | DEPT | SALARY |
|---|---|---|---|
| E001 | 김지훈 | 인사팀 | 4000 |
| E002 | 이수민 | 개발팀 | 4500 |
| E003 | 박준형 | 인사팀 | 3800 |
| E004 | 정유진 | 개발팀 | 4700 |

```sql
SELECT *
  FROM EMPLOYEE A
 WHERE SALARY >= (SELECT AVG(SALARY) FROM EMPLOYEE WHERE A.DEPT= DEPT);
```

분석

*서브쿼리의 조건에 메인 쿼리의 컬럼이 있기 때문에 독립적으로 실행 불가.*

1. 메인 쿼리 첫 번째 튜플의 DEPT='인사팀'을 서브쿼리에 대입
- 메인쿼리 첫 번째 튜플의 DEPT값은 '인사팀'. 따라서 서브쿼리는 '인사팀'소속의 직원 급여 평균 반환.
- 즉, 서브쿼리 : 3900
- 메인쿼리는 첫 튜플 급여 4000 > 3900 이므로 TRUE
- 따라서 첫 번째 튜플을 반환
2. 메인 쿼리 두 번째 튜플의 DEPT='개발팀'을 서브쿼리에 대입
- 이 때, 서브쿼리의 반환값 : 4600
- 메인쿼리는 두 번째 튜플 급여 4500 < 4600 이므로 FALSE
- 두 번째 튜플은 반환하지 않는다.
3. 메인 쿼리 세 번째 튜플에 대해 동일하게 진행
- 세 번째 튜플은 반환하지 않는다.
4. 메인 쿼리 4번째 튜플에 대해 동일하게 진행
- 네 번째 튜플을 반환한다.
5. 최종적으로 EMPLOYEE 테이블의 첫 번째와 네 번째 튜플의 모든 컬럼을 반환한다.

[EMPLOYEE] 테이블
| EMP_ID | EMP_NAME | DEPT | SALARY |
|---|---|---|---|
| E001 | 김지훈 | 인사팀 | 4000 |
| E004 | 정유진 | 개발팀 | 4700 |

## WHERE 절에서 다중 행 서브쿼리 사용

**다중 행 서브쿼리** : 실행 결과 튜플이 1개 이상인 서브 쿼리. 출력 튜플이 2개 이상일 경우, 단일 행 연산자 사용 불가(다중 행 연산자 사용)

다중 행 연산자 : IN, ANY, ALL, EXISTS/NOT EXISTS

*실무에서는 IN과 EXISTS계열 주로 사용.*


### 예시

아럐 예시는 모두 공통적으로 아래 EMPLOYEE 테이블과 BONUS 테이블을 사용.

[EMPLOYEE] 테이블
| EMP_ID | EMP_NAME | DEPT | SALARY |
|---|---|---|---|
| E001 | 김지훈 | 인사팀 | 4000 |
| E002 | 이수민 | 개발팀 | 4500 |
| E003 | 박준형 | 인사팀 | 3800 |
| E004 | 정유진 | 개발팀 | 4700 |
| E005 | 오세훈 | 영업팀 | 4200 |

[BONUS] 테이블
| BONUS_ID | EMP_ID |
|---|---|
| B001 | E001 |
| B002 | E004 |
| B003 | E005 |




#### IN 연산자 다중 행 서브쿼리 예시

```sql
SELECT *
  FROM EMPLOYEE
 WHERE EMP_ID IN (SELECT EMP_ID FROM BONUS);
```

실행 순서
1. SELECT EMP_ID FROM BONUS
- 현재 서브쿼리는 비연관 서브쿼리이므로 독립적으로 먼저 실행
- 결과 : 
| EMP_ID |
|---|
| E001 |
| E004 |
| E005 |
2. 서브쿼리를 결과로 치환하여 메인쿼리 계산
- 서브쿼리문을 그 결과로 치환
```sql
SELECT *
  FROM EMPLOYEE
 WHERE EMP_ID IN ('E001', 'E004', 'E005');
```
- 결과 : 
| EMP_ID | EMP_NAME | DEPT | SALARY |
|---|---|---|---|
| E001 | 김지훈 | 인사팀 | 4000 |
| E004 | 정유진 | 개발팀 | 4700 |
| E005 | 오세훈 | 영업팀 | 4200 |


#### ANY, ALL 연산자 다중 행 서브쿼리 예시

**ANY**

```sql
SELECT *
  FROM EMPLOYEE
 WHERE SALARY >= ANY (
       SELECT SALARY
         FROM EMPLOYEE
        WHERE DEPT = '개발팀'
    );
```

1. SELECT SALARY FROM EMPLOYEE WHERE DEPT = '개발팀'
- 비연관 서브쿼리이므로 독립적으로 먼저 실행
- 결과 : 
| SALARY |
|---|
| 4500 |
| 4700 |
2. 서브쿼리 치환 + 메인쿼리 실행
- 다음과 같이 치환된다.
```SQL
SELECT * FROM EMPLOYEE WHERE SALARY >= ANY (4500, 4700) ;
```
- SALARY >= ANY (4500, 4700)는 SALARY >= 4500 **OR** SALARY >= 4700과 같다. 즉, SALARY >= 4500과 같은 의미를 갖는다.
- 출력결과 : 

| EMP_ID | EMP_NAME | DEPT | SALARY |
|---|---|---|---|
| E002 | 이수민 | 개발팀 | 4500 |
| E004 | 정유진 | 개발팀 | 4700 |


**ALL**
```sql
SELECT *
  FROM EMPLOYEE
 WHERE SALARY >= ALL (
       SELECT SALARY
         FROM EMPLOYEE
        WHERE DEPT = '개발팀'
    );
```

1. SELECT SALARY FROM EMPLOYEE WHERE DEPT = '개발팀'
- 비연관 서브쿼리이므로 독립적으로 먼저 실행
- 결과 ANY에서와 동일
2. 서브쿼리 치환 + 메인쿼리 실행
- 다음과 같이 치환된다.
```SQL
SELECT * FROM EMPLOYEE WHERE SALARY >= ALL (4500, 4700) ;
```
- SALARY >= ALL (4500, 4700)는 SALARY >= 4500 **AND** SALARY >= 4700과 같다. 즉, SALARY >= 4700과 같은 의미를 갖는다.
- 출력결과 : 

| EMP_ID | EMP_NAME | DEPT | SALARY |
|---|---|---|---|
| E004 | 정유진 | 개발팀 | 4700 |

#### EXISTS, NOT EXISTS 연산자 다중 행 서브쿼리 예시

**EXISTS**

*대표적인 연관 서브쿼리 exists*

```sql
SELECT *
  FROM EMPLOYEE A
 WHERE EXISTS (SELECT 1 FROM BONUS B WHERE A.EMP_ID = B.EMP_ID) ;
```

실행 순서
1. 연관 서브쿼리이므로 메인->서브 순서로 해석
2. A 테이블의 1열에 대하여
- 서브쿼리 : E001 = E001인 B 1열 존재. 따라서 1개 열 반환.
- WHERE절 : 서브쿼리에서 반환되는 열이 존재하기 때문에 TRUE
- 따라서 1열을 출력 결과에 포함.
3. A테이블의 2열에 대해
- 서브쿼리 수행. 반환 없음
- WHERE 절 FALSE
- 출력x
4. A테이블 3열에 대해. 3과 동일
5. A테이블 4열에 대해. 1과 동일
6. A테이블 5열에 대해. 1과 동일
7. 출력 결과 : 
| EMP_ID | EMP_NAME | DEPT | SALARY |
|---|---|---|---|
| E001 | 김지훈 | 인사팀 | 4000 |
| E004 | 정유진 | 개발팀 | 4700 |
| E005 | 오세훈 | 영업팀 | 4200 |


**NOT EXISTS**

```sql
SELECT *
  FROM EMPLOYEE A
 WHERE NOT EXISTS (SELECT 1 FROM BONUS B WHERE A.EMP_ID = B.EMP_ID) ;
```

EXISTS와 같은 순서로 수행하되, 서브쿼리의 결과값이 존재하면 FALSE, 없으면 TRUE.

출력결과 : 

| EMP_ID | EMP_NAME | DEPT | SALARY |
|---|---|---|---|
| E002 | 이수민 | 개발팀 | 4500 |
| E003 | 박준형 | 인사팀 | 3800 |

## WHERE 절에서 다중 컬럼 서브쿼리 사용

**다중 컬럼 서브쿼리** : 서브쿼리 결과가 여러 컬럼으로 반환될 때 사용하는 방식.

IN 연산자와 많이 사용.

형식 : 
```sql
WHERE (컬럼1, 컬럼2) IN ((값1, 값2), (값3, 값4))
```

의미 : 
```sql
WHERE (컬럼1 = 값1 AND 컬럼2 = 값2)
   OR (컬럼1 = 값3 AND 컬럼2 = 값4)
```

### 예시

예시 테이블
[EMPLOYEE] 테이블
| EMP_ID | EMP_NAME | DEPT | POSITION | SALARY |
|---|---|---|---|
| E001 | 김지훈 | 인사팀 | 사원 | 4000 |
| E002 | 이수민 | 개발팀 | 대리 |  4500 |
| E003 | 박준형 | 인사팀 | 대리 |  4300 |
| E004 | 정유진 | 개발팀 | 과장 |  4700 |
| E005 | 오세훈 | 영업팀 | 사원 |  4200 |

[PROMOTION] 테이블
| TARGET_ID | DEPT | POSITION |
|-----------|------|----------|
| T001 | 인사팀 | 대리 |
| T002 | 영업팀 | 사원 |

```sql
SELECT *
  FROM EMPLOYEE
 WHERE (DEPT, POSITION) IN (SELECT DEPT, POSITION
                              FROM PROMOTION_TARGET);
```

실행 순서
1. 비연관 서브쿼리이므로 서브쿼리를 먼저 계산
- 서브쿼리 결과 : 
| DEPT | POSITION |
|------|----------|
| 인사팀 | 대리 |
| 영업팀 | 사원 |
2. 메인쿼리 진행 - 서브쿼리 대체
```sql
SELECT *
  FROM EMPLOYEE
 WHERE (DEPT, POSITION) IN (('인사팀', '대리'), ('영업팀', '사원'))
```
